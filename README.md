# 股权授予核对台 · Fictional Equity Administrator

虚构股权激励计划的授予/归属/行权核对系统。用户登记 **授予日期、数量、悬崖期、归属计划**（可标记需要条件的批次），
系统按任意 **查询日期** 分别显示该授予在当天的：

| 阶段 | 含义 |
|---|---|
| 未归属 unvested | 截至查询日尚未归属（含条件未满足的批次） |
| 已归属 vested | 截至查询日累计归属数量 |
| 已行权 exercised | 截至查询日已 **确认** 的行权数量 |
| 待确认预留 pendingReserved | 当天仍为 PENDING 的申请占用的额度 |
| 可行权 exercisable | 还能提交行权申请的数量 |

> 各阶段在每个查询日 **独立按时间轴重建**，不用一个"余额"覆盖所有阶段：
>
> ```
> total     = unvested + vested
> vested    = exercised + pendingReserved + exercisable
> ```
>
> 本系统全部规则均为虚构演示，**不提供税务、法律或投资建议**。

## 技术栈

- **Angular 18**：授予时间轴、额度解释（堆叠条 + 公式）、条件批次人工标记、行权申请/确认/取消。
- **Spring Boot 3 / Java 21**：全部数量用 `BigDecimal`（DECIMAL(18,4)，4 位小数股数，HALF_EVEN），
  最后一个归属节点吸收舍入余数，节点合计与授予总量精确相等。
- **PostgreSQL 16**：`grants` / `vesting_nodes` / `exercise_requests` 三张表，数量列 `NUMERIC(18,4)`。

## 归属规则（虚构）

1. 月度归属：`月份额 = 总量 / 归属月数`（4 位小数，HALF_EVEN）。
2. 悬崖期：第 `cliffMonths` 月一次性归属前 N 个月的份额（如 12 个月悬崖 → 节点 12 = 1200/4800）。
3. 悬崖后每月一个节点；最后一个节点 = 总量 − 此前节点之和（吸收舍入余数）。
4. **月底授予日**：用 `LocalDate.plusMonths` 自然钳制（1 月 31 日 + 1 月 = 2 月 28/29 日）。
5. **条件批次**：标记 `conditional` 的节点即使计划归属日已过，也必须由管理员登记"条件满足日"后才归属；
   实际归属日取 `max(计划归属日, 条件满足日)`。

## 行权规则（虚构）

- PENDING 申请即 **预留/占用** 可行权额度；多个申请合计不得超过当天可行权数量，超出返回 422。
- 确认（CONFIRMED）后从"预留"转入"已行权"。
- 取消未确认（CANCELLED）申请立即释放预留，回到可行权池。
- 历史查询按当日状态重建：取消日/确认日当天及以后才视为已取消/已确认，之前仍按 PENDING 计算。

## 一键启动（Docker Compose）

```bash
docker compose up --build
# API:   http://localhost:8080
# 前端:  cd frontend && npm install && npm start  -> http://localhost:4200
```

`demo` profile 会播种题目要求的核对案例（见下）。

## 本地开发

后端（需要 JDK 21、Maven、本机或 compose 中的 PostgreSQL）：

```bash
docker compose up -d db
cd backend
mvn spring-boot:run -Dspring-boot.run.profiles=demo
```

前端：

```bash
cd frontend
npm install
npm start            # 代理 /api -> localhost:8080
```

## 阶段核对案例（测试 + 播种数据均覆盖）

授予：**2025-01-31（月底）**，4,800 股，12 个月悬崖，48 个月归属（每月 100 股），节点 24 需条件。

| 查询日 | unvested | vested | exercised | pendingReserved | exercisable | 事件 |
|---|---:|---:|---:|---:|---:|---|
| 2025-01-31 | 4800 | 0 | 0 | 0 | 0 | 授予日 |
| 2026-01-30 | 4800 | 0 | 0 | 0 | 0 | 悬崖前一天 |
| 2026-01-31 | 3600 | **1200** | 0 | 0 | **1200** | 悬崖日，12 个月一次性归属；提交 EX-001 500 |
| 2026-01-31 | 3600 | 1200 | 0 | 500 | 700 | EX-001 后；申请 701 被拒（>700） |
| 2026-01-31 | 3600 | 1200 | 0 | 1200 | 0 | EX-002 700 后，额度用尽 |
| 2026-02-14 | 3600 | 1200 | 0 | 1200 | 0 | 取消前一天（历史重建） |
| 2026-02-15 | 3600 | 1200 | 0 | 500 | **700** | 取消 EX-002，释放 700 |
| 2026-03-09 | 3500 | 1300 | 0 | 500 | 800 | 确认前一天，EX-001 仍 PENDING |
| 2026-03-10 | 3500 | 1300 | **500** | 0 | 800 | 确认 EX-001 |
| 2027-01-31 | 2500 | **2300** | 500 | 0 | 1800 | 节点 24 条件未满足，该 100 股不归属 |
| 2027-03-14 | 2300 | 2400 | 500 | 0 | 1900 | 条件标记（3/15）前一天 |
| 2027-03-15 | 2300 | **2500** | 500 | 0 | 2000 | 条件满足，节点 24 归属 |
| 2029-02-01（条件未标记） | 100 | **4700** | 500 | 0 | 4200 | 所有常规节点到期，条件批次仍不归属 |
| 2029-02-02（条件 2/2 标记） | 0 | 4800 | 500 | 0 | 4300 | 人工标记后最后 100 股归属 |

注意 2026-02-28 的节点来自 `2026-01-31 + 1 月` 的月底钳制；4800/48 可整除，
另一个 1000 股/48 月（无悬崖）的案例验证余数精确：47 × 20.8333 + 20.8349 = 1000.0000。

自动化核对：

```bash
cd backend && mvn test

# 超额拒绝、预留、取消释放（含历史日重建）、确认、全部归属、舍入余数
```

## 主要 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/grants` | 登记授予并生成全部月度节点（body 可含 `conditionalMonths`） |
| GET | `/api/grants/{id}/timeline?asOf=YYYY-MM-DD` | 查询日的全部阶段数量 + 时间轴 + 行权记录 |
| POST | `/api/grants/{id}/nodes/{seq}/mark-condition` | 人工标记条件批次满足 |
| POST | `/api/grants/{id}/exercises` | 提交行权申请（超过可行权 → 422） |
| POST | `/api/exercises/{id}/confirm?date=` | 确认 |
| POST | `/api/exercises/{id}/cancel?date=` | 取消未确认申请并释放额度 |
